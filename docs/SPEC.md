# powder-play 仕様書（ドラフト v0.2）

更新日: 2026-10-11

状態: v0.2 ベータを実装済み。暫定仕様は 12 節に記載。端末実機での検証は未完了。

## 1. 目的

スマートフォンのブラウザー上で、画面の傾き・加速度・回転とタッチ操作を使って、空気・水・粉を動かして遊べる 2 次元ビューアを作る。将来、固体・液体・気体の物質を追加できる構造にする。

本書では、ユーザー指定の要件と、未確定の設計案を分けて記載する。未確定の数値や挙動は、実機での操作感を見て決める。

## 2. 用語と決定状況

- **ビューポート**: ブラウザーで見えている領域。
- **ワールド**: 物質とシミュレーションが存在する 2 次元空間。
- **幕裏**: ビューポートの外にはみ出しているワールド領域。
- **選択オブジェクト**: 選択モードで選び、配置・移動の対象にする物質または物質のグループ。グループの定義は未確定。
- **動作ダイアル**: 二本指の回転操作で表示し、操作モードを選ぶ UI。

| 項目 | 状態 | 内容 |
|---|---|---|
| アプリ名 | ユーザー指定 | `powder-play` |
| 初期物質 | ユーザー指定 | 空気・水・粉を用意する |
| 初期配置 | ユーザー指定 | ワールドのおよそ半分を水、半分を空気とし、粉をおよそ 5% 含める。粉の分布位置は未確定 |
| 気体の性質 | ユーザー指定 | 近距離の気体どうしが、弱く互いに離れようとする |
| 操作モード | ユーザー案 | 選択・配置・流通の 3 モード。起動時は選択モード |
| 二本指操作 | ユーザー案 | ピンチでズーム、スライドでビューポート移動、回転で動作ダイアルを操作 |
| 表示範囲 | ユーザー指定 | ビューポートとワールドを一致させる表示と、各辺がおよそ 10% はみ出す表示を用意する |
| 端末の向き | ユーザー指定（実装制約あり） | 向きの変更を当面避ける。ブラウザーがロックできない場合は検知して一時停止する方針 |
| PC の傾き代替 | ユーザー承認 | 矢印キーで重力方向を操作する |
| 物質プラグイン | ユーザー指定 | 空気・水・粉を最初の要素とし、将来の物質追加を考慮する |
| シミュレーション方式 | 未確定 | セルベース方式を候補とするが、方式は固定していない |
| SvelteKit / テスト環境 | 未確定 | Node.js 22.12 環境で利用するバージョンを別途決める |

## 3. 入力と操作モード

### 3.1 二本指: ビューポートと動作ダイアル

- 二本指の距離を変えるピンチで、ビューポートをズームする。
- 二本指の中心を移動するスライドで、ビューポートを移動する。
- 二本指を回転すると動作ダイアルを表示し、回転量で選択モード・配置モード・流通モードを選ぶ。
- 起動時のモードは選択モード。
- ズーム・移動はワールドの物質を変更せず、表示位置と倍率だけを変える。

**β v0.2 の暫定判定**: 二本指を置いたら、指間距離の変化・中心の移動・二本指の回転量を見て操作を判定する。回転が 16°、距離変化が 8%、または中心移動が 12 CSS px の閾値に先に達した操作として、動作ダイアルまたはカメラ操作に分類する。分類後は指を離すまで同じ操作を続ける。動作ダイアル操作中はカメラを変えず、指を離した時点で強調中のモードを確定する。実機で閾値を調整する。

二本指操作が始まった時点で進行中の一本指操作をどう扱うか（中断・確定など）は未確定。三本以上の指は、初期案では最初の二本だけを操作に使い、残りは無視する。

### 3.2 一本指: モードごとの操作

#### 選択モード（初期モード）

- 粒子をタップして選択する。
- 選択粒子に接している粒子をグループとして表示する。
- 選択状態を保ったままドラッグすると、選択対象を移動する。
- β v0.2 では上下左右の同じ物質を連結グループとし、選択数を最大 256 個に制限する。選択中はグループをシミュレーションから固定し、空白タップまたは `Escape` で解除する。

#### 配置モード

- 選択中のオブジェクトを、一本指で指定した位置に追加する。
- 押し続けている間は連続して追加する。
- β v0.2 では選択元を残して複製し、連続配置は約 120 ms ごとに試みる。未選択時は粉を配置する。配置先のグループ全体がワールド内の空気セルでない場合は配置しない。

#### 流通モード

- 一本指で線を引き、始点から終点へ向かう流れを作る。
- 流れに触れた粒子に、流れの方向へ力を加える。
- β v0.2 では線の始点から終点への平均方向を使い、幅 2 セル、強さ 0.7、約 1.5 秒持続する。

### 3.3 長押しと注目モードの競合

以前の要件では「特定箇所を長押しして注目モードに入り、画面内のボタンを操作する」としていた。一方、新しい配置モードでは長押し中に連続配置する。同じ場所・同じ長押しを両方に割り当てることはできない。

**β v0.2 の決定**: ピンチによるズーム・スライドを注目モードの拡大・移動機能に置き換え、長押しは配置モードの連続配置に使う。モード・表示範囲・センサー・一時停止の操作は常時使える HTML コントロールとして用意する。別個の注目モードは設けない。

### 3.4 PointerEvent とブラウザー標準ジェスチャー

- ゲーム操作面では PointerEvent を使い、ポインター捕捉と `pointercancel` を含む状態遷移を実装する。
- カスタムの二本指操作を行うため、ゲーム操作面に限って `touch-action: none` を使う案とする。これを指定した領域ではブラウザー標準のパン・ピンチズームに頼らず、アプリ側でズーム・移動を実装する。
- ブラウザー全体の拡大を無効にせず、ゲーム操作面の外では標準のページ操作を妨げない。
- 複数指対応、タッチキャンセル、iOS Safari の実機挙動は端末で確認する。

## 4. センサー操作

### 4.1 傾き・重力

端末の `DeviceMotionEvent.accelerationIncludingGravity` を使い、画面座標の重力方向へ物質が移動する案とする。センサー値には端末固有の揺れがあるため、平滑化を行う。画面がほぼ水平で面内の重力成分が小さい場合は、下向きを既定方向とする。

次の式は、W3C のデバイス座標と `screen.orientation.angle`（自然向きから反時計回り）から得た**実装候補**である。画面座標は右・下を正とする。実機の向き別テストで符号を確認する。

```text
a = accelerationIncludingGravity の (x, y)
g = (-a.x, -a.y)
theta = screen.orientation.angle
theta = theta * pi / 180

Gx = gx * cos(theta) - gy * sin(theta)
Gy = -(gx * sin(theta) + gy * cos(theta))
```

| 画面角度 | 静止時の入力例 `(ax, ay)` | 画面上の重力 |
|---:|---:|---|
| 0° | `(0, +g)` | 下 |
| 90° | `(+g, 0)` | 下 |
| 180° | `(0, -g)` | 下 |
| 270° | `(-g, 0)` | 下 |

### 4.2 加速度・振り

振り操作は、重力成分を平滑化した値と `accelerationIncludingGravity` の差分から一時的な加速度を推定する案とする。発火閾値・力・継続時間は未確定。センサーが利用できない場合は振り操作を無効にし、エラーをユーザーに分かる形で通知する。

### 4.3 回転

`DeviceMotionEvent.rotationRate.gamma` は画面法線方向（Z 軸）の回転速度として扱える。回転を渦・横方向の力に使う案はあるが、効果と強さは未確定。

### 4.4 権限と実行環境

- センサー API の利用には HTTPS または localhost が必要。
- iOS Safari ではセンサー権限要求が必要な環境があるため、ユーザー操作（開始ボタン等）の中で権限を要求する。
- センサー値が `null`、権限が拒否された、または API が未対応の場合も、タッチと PC キーによる操作は使えるようにする。

## 5. ワールドと物質

### 5.1 初期状態と表示

- 2 次元のワールドを用意し、初期状態はおよそ半分を水、半分を空気、粉をおよそ 5% とする。
- 粉は水に浮き、空気中では上昇しない性質を持たせる。
- 空気は水色・完全透明、水は青・不透明度 10%、粉は銀色・完全不透明とする。
- 色の具体的な RGB 値と背景色は未確定。空気の不透明度が 0 の場合、その水色は描画上見えず、背景が透ける。
- 初期の粉をどこに分布させるか、物質の総量をどう数えるかは未確定。

### 5.2 物質プラグイン

空気・水・粉は、物質ごとに性質と相互作用を持つプラグインとして登録する。将来、固体・液体・気体の追加でシミュレーション全体を書き換えずに済む設計を目指す。

初期の空気を含む気体には、近距離の気体どうしが互いに弱く離れようとする相互作用（反発傾向）を持たせる。これは拡散を促す小さな局所効果とし、気体全体が一方向へ加速したり、止まらず急速に広がり続けたりしないようにする。相互作用の表現はシミュレーション方式に合わせて決める。

プラグインの責務・データ形状は実装時に決める。候補として、識別子、相（固体／液体／気体／粉体等）、密度、色・不透明度、移動・相互作用ルールを持たせる。密度順を「空気 < 粉 < 水」とする案はあるが、粉の動きの詳細を含めて未確定。気体の反発の強さ・作用距離、および空気以外の気体にも適用するかは未確定。

## 6. ワールド表示と解像度

### 6.1 表示範囲とカメラ

- **fit**: ワールド全体を表示する。カメラ倍率は 1.0。
- **bleed**: ワールド中央を 1.2 倍に拡大し、各辺がおよそ 10% はみ出す領域を幕裏とする。
- ピンチ・スライドはシミュレーションのワールドを作り直さず、カメラだけを変更する。
- 初期表示モード、ワールド端での移動制限、リサイズ時の倍率・位置の保持は未確定。

### 6.2 自動解像度

30 フレーム/秒を目標に、画面比率と `hardwareConcurrency` から初期セル数を見積もる。実行中はシミュレーションと描画を含むフレーム処理時間を測り、遅い場合は解像度を下げ、余裕が続く場合は段階的に上げる。解像度を変えるときはセルを最近傍で再サンプリングするため、細かな粒子配置が変わる場合がある。

## 7. 画面向きと PC 操作

### 7.1 画面向きの変更

起動時の画面向きを維持し、別の向きになった場合はシミュレーションと入力を一時停止して、元の向きに戻すよう案内する。ワールドは作り直さず保持する。ビューポートサイズだけが変わり、画面向きが変わらないリサイズではワールドを保持してカメラを更新する。

Web の画面向きロック API はブラウザーによって利用できず、iOS Safari では `screen.orientation.lock()` が未対応である。したがって「物理的な向き変更を常に禁止」は保証できず、対応ブラウザーでロックを試し、非対応環境では検知・一時停止する方針とする。

### 7.2 PC

- 矢印キーで重力方向を設定する。キーを離すと、センサー使用中はセンサー重力、それ以外は下向きに戻す。
- `1`／`2`／`3` で選択／配置／流通、`+`／`-` でズーム、`Space` で一時停止する。

## 8. 実装構成案

シミュレーション、物質、入力、性能計測を UI から分離する。

```text
src/lib/sim/         ワールド状態・シミュレーション
src/lib/materials/   物質プラグイン
src/lib/input/       センサー・PointerEvent・操作モード
src/lib/render/      Canvas 描画・カメラ
src/lib/perf/        性能計測・解像度選択
src/routes/          画面・操作 UI（SvelteKit 採用時）
```

β v0.2 は SvelteKit 2、TypeScript、Canvas 2D とセルベースのシミュレーションで構成する。Cloudflare Workers への配信用に `@sveltejs/adapter-cloudflare` と [`wrangler.jsonc`](../wrangler.jsonc) を使う。

## 12. β v0.2 の実装範囲と暫定値

- **初期物質**: ワールドセルの約 47.5% を水、約 47.5% を空気、約 5% を粉とする。粉は水面直上に層状に置き、重力で落ち着かせる。空気は完全透明、水は青色・不透明度 10%、粉は銀色・完全不透明。空気が透明なので、背景色は Canvas 外側の淡い水色を透過表示する。
- **物質プラグイン**: ID、名称、相、密度、RGBA 色を登録する。初期相は気体・液体・粉体。密度を使った移動則により、粉は空気中を落下し、水に触れると沈まずに留まり、水は粉を上へ押し出す。
- **気体の反発**: 気体プラグインの `repulsion` 確率は 1 ステップあたり 0.0006。セル近傍の液体／粉体との境界で、空気セルが局所的に置き換わる希な拡散として近似する。分子単位の連続的な物理モデルではないため、強さは実機で調整する。
- **入力**: PointerEvent を使う。一本指の配置は選択グループを複製し、未選択なら粉を配置する。流通は線の始点から終点へ短い力を加える。二本指の回転は操作モード、距離と中心移動はカメラを操作する。
- **センサー**: 重力加速度で重力方向、線形加速度で短い力、`rotationRate.gamma` で弱い渦状の力を与える。権限要求はボタン操作中に行う。ブラウザーが現在の画面向きをロックできない場合は向き変更を検知して一時停止する。
- **解像度**: 初期セル数を概ね 12,000 + 1,700 × 論理 CPU コア数（上限 60,000）で見積もる。描画とシミュレーションを含む 30 フレーム分の実測時間を用い、遅い場合はセル数を減らし、余裕が続く場合は増やす。処理目標は約 30 fps。
- **操作の代替**: 矢印キーで重力、`1`／`2`／`3` でモード、`+`／`-` でズーム、`Space` で一時停止できる。
- **検証状況**: 単体テスト、型チェック、本番ビルドは実装後に実行する。Android Chrome／iOS Safari の実機センサー・複数指・画面向き・性能確認は未完了。
